# 问题与目标
- 转接提示总是“成功”，缺少真实确认；需要准确区分“已请求/成功/失败/未确认超时”。
- “调度忙，来电已排队”在仅有一个来电时也显示；需按真实队列/并发条件显示。
- 转接后仍占用麦克风；需在会话结束或全空闲时释放麦克风资源。
- 多路并发时仅首路能听到调度员声音；需确保普通通话为 sendrecv 且多路共享同一麦克风流。

# 技术方案
## 1. 转接结果确认（前端 + 后端联合）
- 前端：发起转接后标记 `transferring[sessionId]`，仅提示“已发送转接请求”。在以下事件后更新结果：
  - 原会话 `ended`：若后端检测到目标通道已建立，提示“转接完成”；否则维持“未确认”直到超时。
  - 原会话 `failed`：提示“转接失败”。
- 后端：新增 `dispatcher_api.php?action=check_transfer`（POST）
  - 入参：`source_uuid`、`target_ext`、`timeout_ms`（默认30000）
  - 逻辑：
    - 通过 `event_socket::api('show channels as json')` 获取活动通道，匹配 `caller_id_number`/`destination_number` 与 `target_ext`；或判断 `uuid_exists`/`uuid_getvar ... bridge_uuid`。
    - 若存在匹配且 `callstate=ACTIVE` → 返回 `{success:true}`；否则轮询直到超时，返回 `{success:false, reason:'timeout'}`。
- 前端轮询：
  - 在 `transferLine()` 发起后，每1s 调用一次 `check_transfer`（最多30s），收到成功立即提示“转接完成”。超时提示“未确认”。

## 2. 忙/排队提示的精确触发
- 更新 `updateBusyQueueBanner()` 条件：
  - 仅当当前存在至少一条已建立/处理中（`isCallEstablished || sessions.length>0`）且 `incomingCount >= 1` 才显示；
  - `incomingCount` = 活动会话中 `direction==='incoming' && !isEstablished()` 的数量。
- 移除 `onIncomingCall` 中的 `forceShow`；改为在 `renderLinesGrid()` 后统一计算。
- 添加队列位置（可选）：在 `dispatcher_api.php?action=get_queue_position` 返回当前来电在队列中的位置（如有呼叫中心队列），前端在横幅中动态更新。
- 动画：使用 `fadeIn/fadeOut 300ms`（保留现有实现）。

## 3. 麦克风资源管理
- 在 `jssip-client.js` 增加缓存式麦克风流：
  - 新增 `this._micStream` 与方法 `getOrCreateMicStream()` → 调用 `getUserMedia({audio:true})`，复用同一 `MediaStream`；
  - `makeCall()` 与 `acceptIncomingCall()` 使用该共享流。
- 在会话结束时释放：
  - `session.on('ended'|'failed')` 中，若 `Object.keys(this.sessions).length===0` 则停止 `this._micStream.getTracks().forEach(track.stop())` 并置空；
  - 同时移除所有发送器 `connection.getSenders()` 的音频轨道（`sender.track.stop()`），确保释放占用。

## 4. 通话模式与多路并发可听
- 修正 `setupSessionListeners()` 的 transceiver 策略：
  - 普通通话（`_callType==='normal'`）使用默认 `sendrecv`；不再添加 `recvonly`；
  - 仅在监听模式（`_callType==='eavesdrop' || mode==='listen'`）添加 `recvonly`；
- 在 `makeCall()`/`acceptIncomingCall()` 为每个会话注入共享的麦克风流（见第3点），确保调度员语音同时进入多路会话。

# 文件修改点
- `app/basic_operator_panel/resources/dispatcher-control.js`
  - 扩展 `transferLine()`：移除立即“成功”提示，改为“已请求”；增加轮询 `check_transfer`；原会话结束/失败事件中更新提示。
  - 更新 `updateBusyQueueBanner()`：按 `incomingCount`/会话建立状态计算显示；移除 `forceShow` 路径。
  - 在 `renderLinesGrid()` 中计算 `incomingCount` 并调用横幅刷新。
- `app/basic_operator_panel/resources/jssip-client.js`
  - 新增共享麦克风流缓存与获取方法：`getOrCreateMicStream()`；
  - 在 `makeCall()`、`acceptIncomingCall()` 注入 `mediaStream` 使用共享流；
  - 在 `session.on('ended'|'failed')` 中，全部会话结束后停止共享流与发送器轨道。
  - 修正 `setupSessionListeners()`：普通通话移除 `recvonly`，监听模式保留。
- `app/basic_operator_panel/dispatcher_api.php`
  - 新增 `action=check_transfer`：ESL 查询通道/桥接状态，返回成功/失败/超时。

# 错误处理与安全
- 转接失败：前端展示具体 `reason`（如 `timeout`/`not_found`），并清理 `transferring` 状态。
- 资源释放：确保在停止 `MediaStream` 时捕获异常；仅在无活动会话时执行。
- 并发：轮询与 ESL 查询限制为 30s，总次数约 30；避免高频对后端压力过大。

# 测试用例
1. 转接已注册在线分机：显示“已请求”→原会话 `ended` 后“转接完成”；后端 `check_transfer` 返回成功。
2. 转接未在线分机：显示“已请求”→后端返回 `not_found` 或前端超时 30s 显示“未确认”；无“完成”。
3. 转接外线号码：同上，以通道状态为准；成功/失败准确提示。
4. 忙/排队横幅：
   - 单一路来电时不显示；
   - 一路已接通且有第二路来电时显示；
   - 通话线路切换/调度状态改变时即时刷新与 300ms 动画。
5. 麦克风释放：所有会话结束后，浏览器不再显示麦克风占用；再次拨打时重新申请。
6. 多路并发发言：调度员同时对多路会话可被听见；监听模式仍单向接收（无发送）。

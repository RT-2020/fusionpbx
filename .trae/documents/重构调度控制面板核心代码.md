## 现状要点
- 重复逻辑：
  - 紧急提示音在两处实现：`dispatcher-control.js:2132` 与 `emergency-audio.js:37-93`。
  - 多处直接操作 DOM 和状态提示在 `index.php:1280-2841` 与 `dispatcher-control.js:1978-2009` 重叠。

- 结构分散：页面脚本承担大量业务逻辑（组呼、会议、急呼、分组管理），应集中在控制器中。
- 事件监听与定时器密集：频繁 `setInterval` 刷新与大量 `show()/hide()` 引发重排与重绘。

## 重构架构
- 模块划分：
  - Core 控制器：保留并精简 `DispatcherControl`，统一通话/会议/组呼/中继/急呼逻辑（`resources/dispatcher-control.js`）。
  - SIP 封装：保留 `JsSipClient`，专注 UA、会话、媒体、权限与资源管理（`resources/jssip-client.js`）。
  - 音频警报：保留 `EmergencyAudioService`，去重并仅由控制器调用（`resources/emergency-audio.js`）。
  - 页面桥接：`index.php` 仅承载 UI 元素、少量桥接函数，业务转发到控制器；公共 AJAX/命令封装合并为统一工具（见下）。
- 公共工具（新增一个轻量工具模块，命名建议 `resources/dispatcher-utils.js`）：
  - HTTP/AJAX 包装、统一错误提示、节流/防抖、DOM 查询缓存、命令构造器（`get_transfer_cmd/get_originate_cmd/get_eavesdrop_cmd/get_record_cmd` 从 `index.php:598-617` 收敛）。
  - 事件总线（简版 Pub/Sub），替换零散全局回调与 `window.*` 依赖。

## 性能提升措施
- DOM 操作：
  - 列表渲染差分更新与 `DocumentFragment`，预计减少重排≥40%。
  - 统一 `show/hide` 为 class 切换，减少布局计算。
- 事件/计时器：
  - 刷新节流：空闲时将 `index.php` 刷新间隔翻倍；交互期间暂停刷新（已有基础，进一步完善）。
  - 计时器集中清理，避免遗留任务与内存泄露。
- 懒加载：
  - `EmergencyAudioService` 与日志模块在首次需要时实例化；SIP 模态打开时才加载默认账号数据。
- 资源体积：
  - 去重/合并模块后自然缩减；后续引入打包/压缩（如 `terser`）以进一步压缩。

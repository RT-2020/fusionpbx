# 在会议编辑页启用“紧急会议”并同步到调度急呼面板的实施方案

## 1. 研究背景与分析

### 1.1 目的、范围与背景
- 目的：在 `app/conferences/conference_edit.php` 增加布尔字段“启用紧急会议”，当启用时将该会议基础信息与参与分机同步到 `app/basic_operator_panel/index.php` 的急呼面板选项中，参与分机来自会议编辑页勾选的目标分机；呼叫模式不限制单呼，样式与现有字段保持一致。
- 范围：
  - 表单与持久化：`conference_edit.php`（表单、POST 解析、验证、保存、dialplan XML 构造与权限）
  - 数据接口：`dispatcher_api.php`（新增“紧急会议列表”接口）
  - 前端急呼面板：`index.php`（急呼模态打开时加载与展示同步的会议项）

### 1.3 关键发现
- 会议编辑页已具备“呼叫模式”和“目标分机”字段的完整验证与持久化，参与分机集合可直接来源于 `call_mode_targets`。
- 单呼模式允许；如参与分机为空需定义同步与展示行为（例如校验不通过或提示）。
- 调度面板需要新增数据源（后端接口）以展示“启用紧急会议”的列表，并在选择后把对应分机集合注入当前目录分类展示。

### 1.4 假设与限制
- 数据库允许在 `v_conferences` 增加字段 `emergency_enabled`（boolean，默认 false）。
-后端新增接口返回会议UUID、名称、扩展、模式与参与分机列表；权限沿用当前接口规范。
- 前端呈现以不改动既有目录结构为原则，仅在急呼面板中插入分类项或下拉，选择后将分机集合注入现有目标区。

## 2. 方案设计

### 2.1 数据结构与字段
- 数据库：在 `v_conferences` 新增列 `emergency_enabled`（boolean，默认 false）。可选新增 `emergency_updated_at`（datetime）用于变更追踪。
- 表单字段：`emergency_enabled`（值 'true'/'false' 与现有布尔字段一致）。

### 2.2 表单与持久化（conference_edit.php）
- 读取：在 POST 解析处读取 `$emergency_enabled = $_POST['emergency_enabled'] ?? 'false'`。
- 验证：在现有 `msg` 校验集中处新增：
  - 若 `emergency_enabled === 'true'`：
    - `group_call`：`call_mode_targets` 非空；每个目标必须在域内启用扩展集合中。
    - `all_call`：无需目标校验；参与分机集合由域内启用扩展生成。
    - `single_call`：`call_mode_targets` 包含恰好一个分机；否则提示。
- 持久化：在 `$array['conferences'][0]` 中加入 `emergency_enabled = ($emergency_enabled === 'true') ? 'true' : 'false'`。
- 预载：在 GET 加载会议记录时读出 `$row['emergency_enabled']` 并用于表单初始值。
- UI：在“启用”字段附近添加“启用紧急会议”开关控件，样式跟随 `conference_enabled` 的 switch 或下拉，以保持视觉一致；必要时添加说明文字。
- 提交流程保持：保存成功后继续 `$_SESSION['reload_xml'] = true` 与 dialplan 缓存清理。

### 2.3 新增后端接口（dispatcher_api.php）
- `action=get_emergency_conferences`
  - 查询 `v_conferences`：条件 `domain_uuid`，`conference_enabled='true'`，`emergency_enabled='true'`。
  - 每条记录组装返回：
    - `conference_uuid`、`conference_extension`、`conference_name`、`call_mode`、`description`
    - `participants`：
      - `group_call`：解析 `call_mode_targets`，过滤到域内启用扩展集合中。
      - `all_call`：返回域内所有启用扩展（`v_extensions`）。
      - `single_call`：若 `call_mode_targets` 恰有一个扩展，则返回该扩展；否则返回空集合或省略。
  - 返回 JSON：`{ items: [ { conference_uuid, extension, name, call_mode, participants: ["1006", ...], description } ] }`。
  - 权限沿用 `operator_panel_view` 或定义新的只读权限（与现有接口一致）。

### 2.4 前端集成（index.php 急呼面板）
- 在 `openEmergencyModal()` 或其初始化路径新增请求：
  - 调用 `dispatcher_api.php?action=get_emergency_conferences` 拉取启用紧急会议列表。
  - 在急呼模态中插入“紧急会议”分类/下拉项（不改变既有布局）。
  - 选择某项后，将其 `participants` 列表注入现有目标输入/集合（例如设置隐藏域或缓存变量），维持当前发起逻辑；单呼允许现有代码路径继续工作。
- 状态与日志：沿用现有状态栏与 `DispatcherLogger` 行为；必要时标记调用来源为“emergency_conference”。

### 2.5 错误处理与交互
- 保存校验失败：与现有 `msg` 提示一致返回页面并保留表单值。
- 接口异常：急呼模态加载失败时，显示提示（toast/modal），保留其他功能可用。
- 参与分机为空：选择紧急会议项时若 `participants` 为空，前端提示并禁止发起。

### 2.6 依赖与安全
- 不新增外部库；沿用现有数据库、权限与 API 框架。
- 权限：接口受 `operator_panel_view` 控制；会议编辑受 `conference_edit` 权限控制。

### 2.7 测试方法
- 功能：
  - 会议编辑页添加/编辑会议，启用紧急会议，验证不同 `call_mode` 下的目标分机校验与保存结果。
  - 调度面板急呼模态显示“紧急会议”项；选择后将目标分机插入现有分类并可发起急呼。
- 兼容：Chrome/Firefox/Edge 前端显示与接口请求；多域场景下仅返回当前域的会议。
- 性能：在会议数较多时接口响应与模态渲染是否顺畅。

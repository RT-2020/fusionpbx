# 目标与范围
- 在 `app/conferences/conference_edit.php` 会议编辑页，使用现有“用户列表”作为授权名单，并新增“启用拨入授权”开关；当启用时，只有被授权用户才能拨打会议分机（如 789789、9999）。
- 在拨入路径上增加授权校验：来话进入会议前，通过脚本核验来话身份是否映射到授权用户；未授权拒绝并记录审计。
- 产出可验证的审计记录，满足：授权方式、授权时间戳、授权操作人员信息、（可能的）设备标识、授权验证结果；并形成 789789 与 9999 的测试记录条目。

## 数据模型与审计
- 使用现有子表 `v_conference_users` 作为授权名单（存储被授权 `user_uuid` 与 `conference_uuid`）。
- 在主表 `v_conferences` 新增布尔字段（文本型）`enforce_authorized_callers`（默认 `false`），表示是否启用拨入授权校验。
- 新增审计表 `v_conference_authorization_logs`（域级）：
  - 字段（建议）：`conference_authorization_log_uuid`、`domain_uuid`、`conference_uuid`、`user_uuid_resolved`（可空）、`extension_uuid_resolved`（可空）、`caller_id_number`、`sip_from_user`、`sip_user_agent`、`network_addr`、`authorized`（true/false）、`reason`（文本）、`insert_date`（timestamptz）。
  - 由运行期 Lua 校验脚本插入；若无法解析用户映射，则 `user_uuid_resolved` 为空、`reason` 填写说明。
- 审计字段复用：会议主表已有 `insert_date/update_date` 与 `insert_user/update_user`（`app/conferences/app_config.php`），用于记录“授权名单更新”的操作者与时间。

## 身份解析与授权规则
- 身份解析（来话 → 用户）：
  - 从通道变量尝试解析来话身份，解析顺序：
    1. `sip_from_user`（FreeSWITCH 目录用户标识）
    2. `caller_id_number`（主叫号码）
  - 映射到分机：查询 `v_extensions`（当前域）满足 `extension = :num` 或 `number_alias = :num` → 得到 `extension_uuid` 与 `extension`。
  - 映射到用户：查询 `v_extension_users`（分机-用户关联）→ 得到 `user_uuid` 列表；若无关联，且 `sip_from_user` 存在，则尝试以 `v_users.username = sip_from_user` 作为兜底。
- 授权判定：
  - 查询 `v_conference_users` 是否存在 `conference_uuid = :conf` 且 `user_uuid` 在解析得到的集合内；存在则“授权通过”，否则“未授权”。
  - 当 `enforce_authorized_callers = false` 时，不执行校验（保持现有行为）。

## 拨号计划修改（XML 构建）
- 在 `conference_edit.php` 的拨号计划 XML 构建处（`app/conferences/conference_edit.php:274-307`），当 `enforce_authorized_callers = true`：

## 运行期脚本（Lua）
- 新建：`app/conference_authorize/check.lua`
  - 输入：读取 `conference_uuid`、`domain_uuid`（可从 `session:getVariable('domain_uuid')` 或通过查询）、`enforce_authorized_callers`、来话变量（`sip_from_user`、`caller_id_number`、`sip_user_agent`、`network_addr`）。
  - 逻辑：
    1. 若 `enforce_authorized_callers` 不为真，直接返回（授权通过）。
    2. 解析来话身份 → 分机 → 用户映射（如上规则）。
    3. 以映射的 `user_uuid` 集合查询 `v_conference_users` 判定授权。
    4. 写入 `v_conference_authorization_logs` 一条审计记录（含授权结果与设备标识）；设置通道变量 `conference_authorized=true/false` 与 `conference_authorize_reason`。
    5. 授权通过：返回到拨号计划继续；未通过：可播放简短提示音，随后 `session:hangup()`。
- 组呼/全呼脚本协作：在 `app/conference_invite/index.lua` 开始处调用上述校验；若未通过，拒绝继续邀请并退出；记录同样的审计。

## 审计与测试记录（789789 / 9999）
- 文档记录条目结构（填入 `移动台组呼全呼.md`）：
  - “授权方式”：会议编辑页选择用户 + 启用拨入授权开关
  - “授权时间戳”：`v_conferences.update_date`（保存操作时间）
  - “授权操作人员”：`v_conferences.update_user`（保存操作者 user_uuid；文档中可展示 `username`）
  - “设备标识”：来自来话侧 `sip_user_agent`、`network_addr`、`caller_id_number`、`sip_from_user`
  - “授权验证结果”：来自 `v_conference_authorization_logs.authorized` 与 `reason`；文档中附通话 `uuid`（`call_uuid`）便于交叉验证。
- 测试用例流程（两个分机：789789、9999）：
  1. 在会议编辑页为 789789（或 9999）选择授权用户，勾选“启用拨入授权”，保存。
  2. 使用授权用户所绑定分机/账户拨打该会议分机，预期：入会成功；记录一条审计“authorized=true”。
  3. 使用未授权用户拨打，预期：拒绝并挂断；记录“authorized=false，reason=not in authorized list”。
  4. 从移动台/外部网关拨打，依据映射规则判定；在文档中记录通道变量采集到的设备标识与授权结果。

## 错误处理与兼容
- 当无法解析来话身份到任何用户时：审计一条“authorized=false，reason=unresolved identity”，拒绝拨入（仅在启用授权时）。
- 性能与高并发：授权校验仅一次查询（若启用），对单呼/组呼/全呼路径影响有限；组呼/全呼的并发邀请逻辑维持不变。
- 回退策略：关闭“启用拨入授权”开关可恢复现有行为（不校验）。

## 依赖与安全

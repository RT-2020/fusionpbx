## 目标与调整
- 将 `#dispatcher-alerts` 从控制面板刷新区域 `#ajax_response` 中移出，避免因 AJAX 重绘导致弹窗被清空与隐藏。
- 栅格“接听”入口统一为按会话ID精确操作，确保多路来电独立可操作。
- 重要更新1：重建弹窗时按每个会话的 `remote_identity` 填充 UI 文本，不使用全局 `incomingCallerInfo`。
- 重要更新2：在 AJAX 写入 `#ajax_response` 完成后，显式调用 `dispatcherControl.updateUI()`，稳定触发重建逻辑。

## 文件与具体改动

### 1) index.php（app/basic_operator_panel/index.php）
- 在 `echo "<div id='ajax_response'></div>"` 之后、`#dispatcher-lines-wrapper` 之前新增全局容器：
  - `<div id="dispatcher-alerts" style="display:none; position:fixed; right:16px; bottom:96px; z-index:9999; max-width:420px;"></div>`
- 在 `loadXmlHttp.prototype.stateChanged` 中（约 278–281 行）在完成 `innerHTML` 写入后增加：
  - `if (window.dispatcherControl && typeof dispatcherControl.updateUI === 'function') { dispatcherControl.updateUI(); }`
  - 作用：每次面板刷新完成后主动触发 UI 更新与弹窗重建，避免刷新与事件流错位导致的短暂空白。

### 2) content.php（app/basic_operator_panel/resources/content.php）
- 删除静态输出的 `#dispatcher-alerts` 容器（约 233 行）。避免其被写入 `#ajax_response` 后在每次刷新复位为“隐藏+空”。

### 3) dispatcher-control.js（app/basic_operator_panel/resources/dispatcher-control.js）
- 栅格入口统一按ID：将未接通入呼的“接听”按钮改为 `acceptIncomingById(id)`（已变更位置约 556 行）。
- 容器隐藏逻辑统一：在 `acceptIncomingById`、`rejectIncomingById`、统一入口 `acceptCall/rejectCall` 中，仅当 `.incoming-call, .trunk-incoming-call` 总数为 0 时执行 `hide()`。
- 中继提示追加：将 `showManualTrunkPrompt` 与 `showAutoTrunkPrompt` 对 `#dispatcher-alerts` 的 `.html(html)` 改为 `.append(html)`（约 728、746 行），避免覆盖清空队列。
- 新增/强化重建函数 `rehydrateAlertsFromSessions()`：
  - 数据源：使用 `sipClient.getIncomingSessions()` 获取 incoming 会话ID列表；对每个会话通过 `sipClient.sessions[sessionId]` 提取 `remote_identity.display_name` 与 `remote_identity.uri.toString()` 构造卡片内容；不要使用 `incomingCallerInfo`。
  - 幂等：若 `#incoming-<sessionId>` 已存在则跳过，避免重复追加。
  - 展示：若存在 incoming 列表则 `show()` 容器，否则 `hide()`。
  - 调用：在 `updateUI()` 末尾调用；此外在通话事件（`incomingCall`、`callEstablished`、`callEnded`、`callFailed`）后也调用一次。
- 可选防抖：为 `rehydrateAlertsFromSessions()` 增加轻量防抖（50–100ms），减少连续刷新下的抖动。

### 4) jssip-client.js（app/basic_operator_panel/resources/jssip-client.js）
- 稳定会话ID：仅在 `newRTCSession` 的 `incoming` 分支首次生成并赋值 `session._customId`；接听阶段不再改写。
- 新增查询：`getIncomingSessions()` 返回 `incomingSessions` 键列表。
- 事件清理：在 `session.on('ended')` 与 `session.on('failed')` 中按 `_customId` 清理 `sessions` 与 `incomingSessions` 对应项；然后调用 `endCall(session)`。

## 错误处理与体验
- 所有失败提示包含 `sessionId` 与当前状态（incoming/connected/ended），并在必要时移除残卡。
- 若检测到 `#dispatcher-alerts` 不存在（主题裁剪等），在运行时动态创建并追加至 `document.body`。

## 测试案例
- 双路入呼：1413→5001，再 1006→5001
  - 观察弹窗持续显示并追加两张卡片；栅格“接听”对两路都能操作。
- 刷新中断：在双路入呼期间触发面板自动刷新或手动刷新
  - 观察刷新完成即触发 `updateUI()` 并重建弹窗；无闪烁与消失现象。
- 中继混合：普通与中继来电并存，提示不覆盖队列；卡片清空后容器隐藏。
- 异常路径：对已结束/已接通会话点击操作，提示明确并清理残卡。

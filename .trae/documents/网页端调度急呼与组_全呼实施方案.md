## 1. 研究背景与分析

### 1.1 目的与范围
- 目的：为网页端调度面板实现“急呼”能力，支持单呼、组呼、全呼，满足状态显示、自动录音与被叫端特殊振铃与自动扬声器等要求，并在现有 FusionPBX/FreeSWITCH 架构内实现。
- 范围：
  - 网页端 Basic Operator Panel（index.php、content.php 与相关 JS 模块）
  - 后端执行接口（exec.php、dispatcher_api.php、dispatcher_conference_api.php）
  - FreeSWITCH Lua 脚本与会议/振铃组能力（conference_center、conference_invite、ring_groups）
  - 录音归档、权限控制、状态监控与日志

### 1.4 假设与限制
- 假设：
  - 端侧 IP Phone/软终端支持 `Alert-Info`/`P-Auto-Answer` 的自动应答与扬声器策略。
  - 会议分机（如 456465、99999）可在 dialplan/数据库中预配置到目标会议室（固定成员/全体）。
  - 录音合规认定以“自动启动+归档目录结构（emergency 或 archive）”为准，无需额外的元数据接口。
- 限制：
  - 并发性能受 ESL 调用、设备响应能力与网络环境影响；网页端现有急呼发起节拍为逐目标 500ms 间隔。
  - `exec.php` 急呼变量串当前存在解析失败问题，需先修复方可稳定使用点对点急呼链路。

## 2. 方案设计

### 2.1 总体策略
- 组呼/全呼：统一走“预配置会议分机”→会议桥模式，满足集中管理与录音；是否采用 PIN 可配置，一般不采用。
- 单呼：采用“点对点急呼（originate→park→bridge）”，确保录音在 emergency 目录；为端侧自动应答/扬声器添加头域。
- 头域策略统一：统一使用 `Alert-Info` 与 `P-Auto-Answer`，未接自动应答目标设为 15 秒；设备不支持时不阻塞流程。

### 2.2 技术路线图
1. 会议桥（预配置分机）落地：
   - 在 `v_conference_rooms`/会议中心配置固定会议号（如 456465=成员 [1006,1413]；99999=全体）及 profile/flags；可选 PIN。
   - 在 dialplan 或 XML Handler 路由表将拨打到这些分机号导向会议中心或邀请脚本。
   - 保持网页端 `dispatcher_conference_api.php` inline 流程，用于前端管理与状态同步；或在网页端直接拨打会议分机（无需动态选人）。
2. 单呼急呼优化：
   - 修复 `exec.php` 急呼 `originate` 变量串：移除重复键、对含 `=` 的头值加引号、去掉 `_undef_` 值、检查空格与 `${uuid}` 注入格式。
   - 统一头域与时序：后端设置 `answer-after=15`，加入 `P-Auto-Answer=speaker`；前端 JsSIP 直接呼叫不参与急呼，避免时序不一致。
   - 完善通道检测与桥接：优化 `get_channel_uuid` 多条件匹配与重试逻辑，桥接失败时回写急呼状态并提示。
3. 状态与录音：
   - 保持网页端“急呼状态栏”与“通话线路网格”显示；
   - 使用 `uuid_record` 自动录音，单呼归档到 `recordings/{domain}/emergency/YYYY/MM/DD`；会议桥归档到 `archive`（可按需扩展）。
4. 权限与安全：
   - 保持 `operator_panel_emergency` 与 `operator_panel_emergency_broadcast` 权限；操作日志通过 `dispatcher_logger` 本地+服务端。
5. 兼容与回退：
   - 设备不支持头域时不阻塞；桥接失败时提示并给出回退呼叫选项。

### 2.3 详细实施步骤

#### A. 会议桥（预配置分机：组呼/全呼）
- 数据库配置：
  - 在 `v_conference_rooms` 配置会议室记录（房间 UUID、room_name/extension、profile、成员策略）与是否使用 PIN。
  - 映射分机：456465→固定成员 [1006,1413]；99999→全体（由会议邀请脚本读取所有启用分机）。
- 路由与脚本：
  - 在 dialplan/XML Handler 将拨打 456465/99999 导向会议中心 `conference_center/index.lua` 或会议邀请 `conference_invite/index.lua`。
  - 若采用邀请脚本，使用 `bgapi originate` 对成员列表批量发起邀请（内置） d:\Project\Project\博创\fusionpbx\fusionpbx\app\switch\resources\scripts\app\conference_invite\index.lua:146–151。
- 网页端集成：
  - 工具栏“组呼/全呼”按钮仅触发拨打预配置分机；状态栏依旧由前端会议 API 更新成员列表与计时 d:\Project\Project\博创\fusionpbx\fusionpbx\app\basic_operator_panel\resources\dispatcher-control.js:1267–1291, 1362–1395。

#### B. 单呼（点对点急呼，统一录音到 emergency 目录）
- 后端 `exec.php` 修复与增强：
  - 变量串安全化：移除 `sip_h_Call-Info=_undef_`，对 `sip_h_Call-Info=<http://…>;answer-after=15` 与 `sip_h_Alert-Info=info=emergency` 使用引号包裹，避免解析 `=` 冲突；保留 `sip_auto_answer=true` 与 `sip_h_P-Auto-Answer=speaker`。
  - 统一时序：`answer-after=15` 用于“未摘机 15 秒自动应答/扬声器打开”；设备不支持时不阻塞。
  - 日志扩充：保留 “Emergency Call Debug - Parameters/Command/Response/Job-UUID”，增加失败时的变量串回显与键值拆解，便于定位。
- 桥接链路：
  - 保持 `&park()`→`bridge_emergency_call`（查找 park 通道 `uuid_bridge` 到调度员），失败时前端提示并回退至直接呼叫。
  - 通道查询 `get_channel_uuid` 扩展匹配项（park application/name/destination_number/caller_id_number/presence_id），保持指数退避至 15 秒上限。
- 录音与状态：
  - 使用 `execute_on_answer=uuid_record ${uuid} start {recordings/{domain}/emergency/Y/M/D/emergency_{ts}_{dest}.wav}` 持续；前端状态栏更新“发起中/接通中/已接通/超时未接”。

#### C. 头域策略与设备兼容
- 统一注入：`sip_auto_answer=true`、`sip_h_Call-Info=<http://fusionpbx/emergency>;answer-after=15`、`sip_h_P-Auto-Answer=speaker`。
- 设备不支持：不阻塞流程；前端状态按通道建立与会议成员接入为准。

#### D. 权限、UI 与日志
- 权限校验：`operator_panel_emergency`（单呼急呼）、`operator_panel_emergency_broadcast`（全呼），API 保持校验 d:\Project\Project\博创\fusionpbx\fusionpbx\app\basic_operator_panel\dispatcher_api.php:271–280。
- UI 按注册状态启用（SIP 已注册） d:\Project\Project\博创\fusionpbx\fusionpbx\app\basic_operator_panel\index.php:1258–1264, 1390–1398。
- 日志：前端 `DispatcherLogger` 本地存储与服务端 `save_call_log` 上报 d:\Project\Project\博创\fusionpbx\fusionpbx\app\basic_operator_panel\resources\dispatcher-logger.js:108–127；`log_emergency_call` 记录各状态 d:\Project\Project\博创\fusionpbx\fusionpbx\app\basic_operator_panel\dispatcher_api.php:311–352。

### 2.4 错误处理策略
- originate 解析失败（Parse Error）：回显变量串与键值，降低为直接呼叫或提示设备/配置问题。
- 通道未找到（超时）：记录 `failed`，状态栏提示“超时未接”，允许重新尝试或改用会议桥。
- 桥接失败：记录 `failed` 并提示；可强拆残留通道（`force_hangup`） d:\Project\Project\博创\fusionpbx\fusionpbx\app\basic_operator_panel\dispatcher_api.php:217–257。

### 2.5 依赖管理
- 不新增第三方库；使用现有 JsSIP、FreeSWITCH ESL、Lua 脚本与 FusionPBX API。

### 2.6 测试方法
- 功能测试：
  - 单呼：正常接通、未接 15s 自动应答、录音落盘 emergency、状态栏正确。
  - 组呼：拨打固定会议分机（如 456465），成员进入、静音/踢出与人数统计正确。
  - 全呼：拨打固定会议分机（如 99999）对所有启用分机邀请并显示状态。
- 性能测试：
  - 并发 100：ESL 非阻塞 `bgapi originate`，网页端节拍与成员轮询在 2s 内稳定，响应延迟 <500ms（UI状态更新与命令排队）。
- 兼容性测试：
  - 浏览器（Chrome/Firefox/Edge）权限与播放；设备（IP Phone/软终端）对 `Alert-Info`/`P-Auto-Answer` 适配矩阵；非支持设备下回退验证。

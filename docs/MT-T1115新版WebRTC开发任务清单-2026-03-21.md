# MT-T1115 新版 WebRTC 开发任务清单

## 1. 文档目的

基于前面的新版分析与实施方案，将需求进一步落成到可执行的开发任务清单。

本清单只面向新版 WebRTC 调度实现，不处理旧版 FusionPBX Operator Panel 的功能扩展。

## 2. 本轮改造范围

| 范围 | 是否纳入 |
| --- | --- |
| `resources/jssip-client.js` | 是 |
| `resources/dispatcher-control.js` | 是 |
| `resources/emergency-audio.js` 或统一音频服务 | 是 |
| `dispatcher_api.php` | 是 |
| `exec.php` | 是 |
| `index.php` 中新版调度区域 | 是 |
| 旧版 `content.php/basic_operator_panel.php` 主逻辑扩展 | 否 |

## 4. 任务拆解明细

## 4.1 `T1` 建立新版统一状态模型

### 目标

让新版所有来电、线路卡片、告警卡片、监控支路使用统一字段。

### 建议新增字段

| 字段 | 含义 | 示例 |
| --- | --- | --- |
| `scene` | 呼叫场景 | `normal_in` / `emergency_in` / `trunk_in_manual` |
| `entityType` | 对象类型 | `user` / `trunk` / `dispatcher` |
| `sessionState` | 会话状态 | `incoming_ringing` / `connected` / `held` / `transferring` |
| `displayNumber` | 展示号码 | `8001` / `10086` |
| `displayName` | 展示名称 | `张三` / `外线中继` |
| `transferMeta` | 转接元数据 | 来源、原主叫、目标 |
| `trunkMeta` | 中继元数据 | 中继类型、模式、来源 |
| `monitorMeta` | 监控元数据 | 监听/强插目标、模式 |

### 主要修改文件

- `resources/jssip-client.js`
- `resources/dispatcher-control.js`

### 验收标准

- `incomingCallerInfo` 不再只有 `isEmergency`
- 新版 UI 不再依赖 `_callType + isEmergency` 组合硬编码

## 4.2 `T2` 补齐新版来电场景识别

### 目标

把新版当前粗分类改为标准导向的精分类。

### 场景列表

| 场景 | 说明 |
| --- | --- |
| `normal_in` | 普通内部来电 |
| `emergency_in` | 紧急来电 |
| `trunk_in_manual` | 人工中继来电 |
| `trunk_in_auto` | 自动中继来电 |
| `blind_transfer_in` | 盲转来电 |
| `attended_transfer_in` | 咨询转接来电 |
| `consult_leg` | 咨询支路 |
| `eavesdrop_leg` | 监听支路 |
| `barge_leg` | 强插/插入讲话支路 |
| `conference_invite` | 会议/组呼邀请 |

### 识别来源

| 来源 | 需要处理 |
| --- | --- |
| `Alert-Info` / `X-Emergency-Call` | 保留急呼识别 |
| `display_name` 关键字 | 保留会议/监听/插入讲话兼容识别 |
| `Referred-By` | 新增转接识别 |
| `Refer-To` | 新增转接识别 |
| `Replaces` | 新增咨询转接识别 |
| `History-Info` | 新增咨询转接识别 |
| `Diversion` | 新增转接/中继辅助识别 |
| trunk prefix / trunk map | 新增中继识别 |

### 主要修改文件

- `resources/jssip-client.js`

### 验收标准

- 来电日志中能明确输出 `scene`
- 页面调试时可以看到普通、急呼、中继、转接被区分开

## 4.3 `T3` 重构新版来电渲染

### 目标

不再以 `isEmergency` 为唯一分支，而是按 `scene` 统一渲染。

### 需要改的函数

- `DispatcherControl.prototype.onIncomingCall`
- `DispatcherControl.prototype.queueIncomingCall`
- `DispatcherControl.prototype.renderLinesGrid`

### 改造要求

| 项目 | 当前问题 | 目标状态 |
| --- | --- | --- |
| 来电卡片标题 | 基本只有“来电/紧急呼叫” | 按场景显示：中继来电、转接来电、咨询转接等 |
| 来电按钮 | 急呼特殊，其他统一 | 按场景给按钮，例如中继桥接、转接确认、监控接入 |
| 线路卡片副标题 | 只显示方向 + `_callType` | 改为 `scene + sessionState + entityType` |
| 状态颜色 | 只有紧急特殊高亮 | 所有重要场景有独立视觉编码 |

### 主要修改文件

- `resources/dispatcher-control.js`

### 验收标准

- 不同场景来电卡片样式和标题明显不同
- 线路卡片可看出“普通 / 中继 / 转接 / 监听 / 强插 / 会议”区别

## 4.4 `T4` 建立新版提示矩阵

### 目标

把“不同声、光提示”从急呼专项扩展为统一提示服务。

### 最小提示矩阵

| 场景 | 声音 | 视觉 |
| --- | --- | --- |
| `normal_in` | 普通铃声 | 中性高亮 |
| `emergency_in` | 紧急循环告警 | 红色高亮 |
| `trunk_in_manual` | 中继提示音 | 橙色高亮 |
| `trunk_in_auto` | 中继提示音 | 橙色高亮 |
| `blind_transfer_in` | 转接提示音 | 青色高亮 |
| `attended_transfer_in` | 咨询转接提示音 | 青色高亮 |
| `eavesdrop_leg` | 轻提示或无铃 | 灰紫监控态 |
| `barge_leg` | 轻提示或无铃 | 橙红监控态 |

### 主要修改文件

- `resources/emergency-audio.js` 或新建统一 `dispatcher-audio.js`
- `resources/dispatcher-control.js`

### 验收标准

- 不再只有急呼有专属提示音
- 新版满足“各种呼叫不同声、光提示”的基础要求

## 4.5 `T5` 打通中继主流程

### 目标

把现在的“中继草案功能”接入新版主来电流程。

### 当前问题

- `handleTrunkIncomingCall()` 存在
- 但 `onIncomingCall()` 没有真正分流过去

### 目标行为

| 场景 | 目标行为 |
| --- | --- |
| `trunk_in_manual` | 弹出人工中继卡片，调度员应答后桥接 |
| `trunk_in_auto` | 自动中继模式下直接进入目标输入和后续桥接 |
| 中继保留 | 中继保留后在线路卡片明确显示 |
| 中继恢复 | 可以从新版 UI 恢复 |

### 主要修改文件

- `resources/dispatcher-control.js`
- `dispatcher_api.php`

### 验收标准

- 中继来电不再走普通来电卡片
- 人工/自动中继流程可分别联调

## 4.6 `T6` 补齐新版监控能力

### 目标

把监听、强插、强拆纳入新版主链路，而不是散落在旧入口或兼容逻辑里。

### 能力清单

| 能力 | 目标 |
| --- | --- |
| 监听 | 新版可发起监听，显示监听态，结束监听 |
| 强插 / 插入讲话 | 新版可发起插入讲话，显示插入讲话态 |
| 强拆 | 新版可对目标通话执行强拆 |
| 挂断双方 | 新版可对桥接双方统一拆除 |

### 主要修改文件

- `resources/dispatcher-control.js`
- `dispatcher_api.php`
- `exec.php`

### 验收标准

- 新版不再依赖旧面板入口去完成监控动作
- 监控动作执行结果可在新版 UI 看到

## 4.7 `T7` 清理控制路由

### 目标

把新版仍需依赖的交换机控制能力拆成干净路由。

### 建议拆分命令

| 命令 | 用途 |
| --- | --- |
| `uuid_record` | 录音 |
| `uuid_eavesdrop` | 监听 |
| `uuid_barge` 或 `uuid_three_way` | 强插 / 插入讲话 |
| `uuid_kill` | 强拆 / 挂断 |
| `uuid_kill_both` | 挂断双方 |
| `uuid_bridge` | 特定桥接辅助 |

### 主要修改文件

- `exec.php`

### 验收标准

- 前端命令名和后端显式分支一一对应
- 不再把监控逻辑混在无关分支里

## 6. 实施建议

本轮最关键的原则只有两条：

1. 不再按单个按钮补丁式开发
2. 所有新增能力都必须挂到 `scene` 和统一状态模型上

否则结果会是：

- 急呼是一套逻辑
- 中继是一套逻辑
- 转接是一套逻辑
- 监听/强插又是一套逻辑

最终仍然无法形成标准要求的“用户状态明了、各种呼叫提示清楚、调度员可方便实施监控”的新版网页调度终端。

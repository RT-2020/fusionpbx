# /plan - 实施规划命令

在进行复杂改动前，先制定详细的实施计划。会自动根据修改的文件路径和操作类型评估风险等级。

## 自动风险评估

本命令会自动分析：
- 📁 修改的文件路径
- 🎯 涉及的功能模块
- ⚠️ 操作类型风险
- 📊 综合风险等级

## 风险等级定义

| 等级 | 图标 | 触发条件 | 要求 |
|------|------|----------|------|
| **严重** | 🔴 | 高风险目录 + 敏感操作 | 必须详细计划 + 测试环境验证 |
| **中等** | 🟡 | 中等风险目录 + 常规操作 | 建议详细计划 |
| **低** | 🟢 | 低风险目录 + 简单操作 | 简化计划即可 |

## 自动识别的高风险场景

系统会自动识别以下高风险场景，无需手动配置：

### 📁 高风险目录
- `app/basic_operator_panel/` - 调度控制面板
- `app/emergency/` - 紧急呼叫系统
- `resources/templates/` - 设备配置模板

### 🔧 高风险操作
- 修改 WebSocket 逻辑
- 修改 FreeSWITCH 集成
- 修改拨号计划
- 修改数据库结构
- 修改权限系统

## 命令输出格式

### 1. 需求复述

简要复述用户的需求，确保理解正确。

### 2. 自动风险评估

根据修改的文件和操作自动评估：

```
📁 修改文件：
  - app/basic_operator_panel/xxx.php (高风险 +3)
  - resources/javascript/xxx.js (中等风险 +1)

🎯 涉及模块：
  - 调度控制面板
  - WebSocket 通信

⚠️ 操作类型：
  - 修改 WebSocket 逻辑 (高风险 +2)

📊 综合风险等级：🔴 严重 (6分)
```

### 3. 风险详情

基于风险等级提供详细的风险分析。

### 4. 实施步骤

详细的步骤清单。

### 5. 验收标准

基于风险等级的验收标准。

### 6. 回滚方案

如果出现问题，如何回滚。

## 执行流程

1. **用户调用 /plan**
2. **AI 自动分析风险**
   - 识别文件路径
   - 匹配风险规则（读取 `.claude/rules/risk-rules.md`）
   - 计算风险分数
   - 确定风险等级
3. **AI 输出计划**
   - 需求复述
   - 自动风险评估
   - 实施步骤
   - 验收标准
   - 回滚方案
4. **等待用户确认**
5. **用户确认后开始实施**
6. **按步骤执行并标记进度**
7. **完成后通知用户验收**

## 何时使用 /plan

### 自动触发场景（无需判断）

- 修改 2 个或更多文件
- AI 检测到高风险目录或操作
- 需求描述不够清晰

### 建议使用场景

- 代码重构
- 新增复杂功能
- 不确定实现方式

### 无需使用场景

- 修复单个文件的简单 bug
- 修改注释或文档
- 调整 UI 样式

## 规则更新

当项目新增高风险模块时，只需更新 `.claude/rules/risk-rules.md`，无需修改 `/plan` 命令本身。

例如，新增了 "AI 助手" 模块：

```yaml
# 在 risk-rules.md 中添加
高风险目录:
  - app/ai_assistant/    # AI 助手模块（新增）
```

这样 `/plan` 就能自动识别新模块的风险，无需手动更新命令定义。
